# Серверное хранение и авторизация

## Зафиксированное решение

- `storageMode` всегда равен `server`.
- Пользователь не выбирает между IndexedDB и сервером.
- Программы, РПД, комментарии проверяющего, статусы и роли хранятся в серверной реляционной БД.
- Все операции чтения и изменения выполняются серверными API после проверки пользователя и его роли.
- `localStorage`, `sessionStorage` и IndexedDB не являются источником рабочих данных. Их можно использовать только для необязательных настроек интерфейса.

## Текущая и целевая инфраструктура

| Слой | Текущее размещение | После переноса на серверы организации |
| --- | --- | --- |
| База данных | Cloudflare D1 | D1 или PostgreSQL/Postgres Pro |
| Авторизация | email + пароль, сессии в D1 | корпоративный OIDC/SSO при необходимости |
| Роли | Таблица `user_profiles` | та же модель ролей |
| Файлы выгрузки | Формируются сервером по запросу | Формируются микросервисом по запросу |

Пароли пользователей хранятся только в виде bcrypt-хэшей в таблице `auth_users`. LDAP/SSO можно подключить позже через корпоративный провайдер удостоверений, который выдаёт OIDC-токены.

## Границы адаптеров

- `lib/server-auth.ts` — единая точка регистрации, входа, сессий и получения авторизованного пользователя. Маршруты API не обращаются к механизму входа напрямую.
- `db/index.ts` — единая точка получения серверной БД.
- `db/providers/d1.ts` — действующий адаптер D1. При переносе вместо него подключается PostgreSQL-адаптер с тем же прикладным контрактом.
- `lib/server-architecture.ts` — зафиксированная конфигурация режима хранения и сведения о текущем и целевом провайдерах.

## Правила доступа

- Автор видит и изменяет только свои программы и РПД.
- Проверяющий получает программы со статусом «На проверке», комментирует поля и принимает решение.
- Администратор управляет ролями и имеет доступ ко всем программам.
- Проверка прав выполняется на сервере для каждого API-запроса; ограничения интерфейса не считаются защитой.

## Перенос микросервиса

1. Создать Cloudflare D1 и применить миграции из `drizzle/`.
2. Задать `INITIAL_ADMIN_EMAIL` через Cloudflare secrets.
3. Зарегистрироваться под email первого администратора.
4. Проверить назначение ролей, автосохранение, РПД, комментарии и DOCX-выгрузку.
5. При будущем переходе на PostgreSQL реализовать адаптер в слое `db` и перенести данные из D1 с сохранением идентификаторов, владельцев, ролей, статусов и комментариев.

Для промышленной эксплуатации также нужен журнал действий: входы, назначения ролей, смены статусов и решения проверяющих.
